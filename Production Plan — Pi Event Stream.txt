Production Plan — Pi Event & Tournament Streaming Control Plane

Below is the complete plan. No code yet. Everything is designed for a solo dev on a Raspberry Pi 3, headless, with an OBS laptop on the same LAN, and a first public event ~12 days after day 30.
1. Reality check and locked-in assumptions

What the Pi does

    Serves the website (public, player, team, moderator, admin, OBS browser sources).

    Owns SQLite + per-event encrypted JSON.

    Controls OBS over WebSocket 5.x on the LAN.

    Talks to Twitch, YouTube, Google, PayPal APIs.

    Serves WebRTC/embedded live view to moderators only.

    Triggers clips, VOD markers, stream start/stop, recording start/stop.

    Stores screenshots (≤1 MB) locally; later USB/cloud.

What the Pi does NOT do

    No 50k-viewer fanout. Public video stays on Twitch/YouTube.

    No transcoding. No heavy ML. No local clip generation.

    No drag-and-drop widget builder in v1.

Hard rule
Every external service is optional per event. If Twitch is down, the event still runs with manual controls.
2. 30-Day Delivery Plan (with 10-day buffer before first event)

Solo, 8–10 hrs/day. Each phase ends with a testable artifact.
Phase 0 — Days 1–2: Foundation

    Repo skeleton, pyproject.toml, virtualenv, .env loader.

    Directory structure (Section 4).

    SQLite schema v1 + migration runner.

    Field-level encryption helper (AES-GCM via cryptography).

    Config loader (env vars + per-event JSON).

    Logging (rotating files + SQLite audit table).

    Health endpoint /healthz.

Deliverable: app boots, DB migrates, health returns JSON.
Phase 1 — Days 3–5: Auth, roles, permissions

    User model, role model, permission matrix.

    Email/password with Argon2id.

    Twitch OAuth, Google/YouTube OAuth.

    Session cookie (HttpOnly, Secure, SameSite=Lax).

    CSRF token middleware.

    2FA (TOTP) + email verification + password reset.

    Audit log for every privileged action.

Deliverable: login, logout, role assignment, audit trail.
Phase 2 — Days 6–9: Core domain (events, teams, players, tournaments)

    Event, Tournament, Bracket, Match, Team, Player, Stat, Sponsor, Charity, AdBreak models.

    Tournament engines: single elim, double elim, round robin, Swiss, groups.

    Tiebreaker rules engine (defaults + per-event override).

    Standings calculator.

    Per-event JSON export (encrypted at rest, decrypted for public API).

Deliverable: create event, add teams, generate bracket, view standings.
Phase 3 — Days 10–13: Public site + registration

    Hybrid rendering: server-rendered shell + client hydration.

    Pages: index, events, event detail, registration, login, schedule, standings, sponsors/charity, About, FAQ, Contact.

    Registration flow per role (attendee, participant, sponsor, moderator, volunteer, vendor).

    Google Forms/Sheets full integration for intake.

    Email via SMTP (verification, reset, invite).

    Per-event branding: logo, colors, fonts, background, light/dark mode.

    i18n scaffold (English default, locale files).

    WCAG AA baseline.

Deliverable: public site live locally, registration working.
Phase 4 — Days 14–16: Player/Team dashboards

    Player dashboard: profile, stats, matches, submissions.

    Team dashboard: roster, stats, matches, submissions, leader confirm.

    Screenshot upload ≤1 MB, PNG.

    Match reporting + dispute flow.

    Half-team confirmation rule for no-API games.

    CSV import for stats.

Deliverable: team submits proof, leader confirms, standings update.
Phase 5 — Days 17–19: Moderator + Admin dashboards

    Moderator dashboard: stream view, OBS controls (role-gated), chat, stats, moderation queue, clip buttons, VOD markers, ad break triggers.

    Admin dashboard: users, roles, permissions, events, sponsors, charity, audit log, backups, exports.

    Sponsor self-register + admin invite.

    Sponsor properties page: images, brand colors, messaging (no raw CSS).

    Spectator page toggle (global + per event).

Deliverable: moderator can run a live event end-to-end manually.
Phase 6 — Days 20–22: OBS integration

    OBS WebSocket 5.x client.

    Scene switching, transitions, source visibility, opacity, color, transforms, filters, media playback, browser source URL updates.

    Naming convention enforcement: underscores, no spaces.

    Persistent cookie auth for browser sources.

    Per-widget routes: /obs/standings, /obs/chat, /obs/sponsors, /obs/charity, /obs/bracket, /obs/timer, /obs/lower_third, /obs/player_card, etc.

    OBS control permission per role.

Deliverable: moderator drives OBS from the website.
Phase 7 — Days 23–25: Live feed, chat, clips

    Embedded Twitch/YouTube for moderators (default).

    WebRTC low-latency option for 1–2 viewers (moderators).

    30s–60s latency buffer, adjustable without restart.

    Twitch + YouTube chat ingest.

    Website moderator chat + website spectator chat.

    Clip trigger via Twitch/YouTube API (last X seconds).

    Clip download after creation.

    Stream start/stop, recording start/stop via OBS.

Deliverable: moderator sees stream, chats, clips, controls OBS.
Phase 8 — Days 26–28: Charity, sponsors, ad breaks, widgets

    Charity totals: manual + PayPal/Stripe/Ko-fi sync.

    Sponsor rotating segments, scheduled ad breaks, per-tier landing pages.

    Ad breaks: OBS scene, timer, manual.

    Widget system v1: JSON templates + config panels per event.

    Per-event branding propagates to widgets and landing pages.

Deliverable: full sponsor/charity/ad-break workflow.
Phase 9 — Days 29–30: Hardening

    Rate limiting, CSRF, XSS, secret rotation.

    nginx reverse proxy config.

    Cloudflare Tunnel option documented.

    Automated backups to external storage.

    External uptime monitor + email alerts.

    Local file + SQLite logging.

    GDPR: data retention, export, delete.

    Full dry-run with test OBS, test Twitch/YouTube, test event.

Deliverable: production-ready Pi deployment.
Days 31–40: Buffer

    Bug fixes, dry runs, load tests, accessibility pass, i18n pass.

    First real event on day ~42.

3. Risk register
Risk	Mitigation
Pi 3 CPU/RAM limits	Headless, no transcoding, SQLite, async I/O, cap concurrent WebRTC to 2
No domain at day 30	Local IP + hosts file; Cloudflare Tunnel optional
OAuth scope changes	Abstract provider layer, config-driven scopes
Twitch/YouTube API limits	Queue + backoff, manual fallback
Encryption key loss	Env var + documented backup, key rotation plan
Solo dev burnout	Phases are independently testable, buffer days
Google Forms API quota	Cache, batch, fallback to embed/link
Sponsor CSS injection	Properties page only, no raw CSS
Spectator chat abuse	Per-event toggle, moderation queue, rate limits

Encryption

    AES-GCM via cryptography.

    Key from env var EVENTSTREAM_MASTER_KEY.

    Field-level encryption for PII/secrets in SQLite.

    Per-event JSON encrypted with derived key from master + event_id.

    Lazy decryption per record or per event on load.

    Key rotation script + audit entry.

9. OBS integration plan

    WebSocket 5.x client, reconnect with backoff.

    Naming: underscores only, no spaces. Enforced by NamingConvention.

    Scenes, sources, filters, transitions discovered and cached.

    Commands gated by role + permission matrix.

    Browser sources authenticate via persistent cookie set once in OBS.

    Per-widget routes so each source can be transformed independently.

    Media playback, filters, opacity, color, transforms all supported.

    Stream start/stop, recording start/stop via OBS.

    Clip trigger via Twitch/YouTube API, not local ffmpeg.

    Ad breaks triggered by OBS scene, timer, or manual button.

10. Live feed plan

    Default: Twitch/YouTube embed for moderators.

    Optional: WebRTC low-latency for 1–2 moderators.

    30s–60s latency buffer, adjustable without restart.

    No Pi transcoding. No 50k fanout.

    Recording/VOD stays on Twitch/YouTube.

    Clips via platform API; download locally after creation.

    Screenshots ≤1 MB PNG, stored locally, later USB/cloud.

11. Security plan

    Argon2id passwords.

    TOTP 2FA + email verification + password reset.

    HttpOnly, Secure, SameSite=Lax session cookies.

    CSRF tokens on all state-changing routes.

    Rate limiting per IP + per user.

    XSS escaping by default; no raw sponsor CSS.

    Security headers: CSP, HSTS, X-Frame-Options, Referrer-Policy.

    Secret rotation script + audit.
